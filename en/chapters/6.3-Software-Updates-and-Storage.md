# 6.3 Software Updates and Storage

## You sent an email to a million ECUs

You sit in the office. On the screen is the OTA backend interface. You selected a firmware package: v2.3.1, which fixes an occasional hysteresis bug in the brake energy recovery module. Target scope: 970,000 models equipped with this ECU worldwide.

You clicked "Publish".

There are now 970,000 recipients on the road around the world. Some are traveling at 200km/h on Germany’s unlimited highways. Some are sleeping in garages at minus 25 degrees Celsius in Norway. Some were bumpy on rural roads in India, with only one bar of cellular signal. Some cars have been scrapped. But the ECU may still be powered on.

You must ensure: not "try to ensure", but "must ensure": each of these 970,000 ECUs will not become bricked.

This is OTA (Over-The-Air). This is not "send a file". OTA is an extreme form of distributed systems engineering: performing irreversible firmware modifications over unreliable network channels on target devices that may never be returned to the factory.

## The wisdom of A/B partitioning: always leave a way out

The first core issue of OTA is not transmission, but the safety net.

If the new firmware is directly overwritten into the running old firmware, the power will be cut off halfway through writing and the car will become bricked. The new firmware has unknown bugs and cannot be rolled back. Signature verification failed, but the old firmware has been overwritten.

So it cannot be upgraded in place.

**A/B Partition** is an elegant solution. Flash is divided into two independent partitions of equal size: Area A and Area B. The current firmware is running in zone A. All new firmware downloaded by OTA is written into area B. Area A is never touched during the entire download and verification process, and it perfectly preserves the complete system state from the moment before you start the upgrade.

After the download is complete, the system verifies the signature and integrity of the Zone B firmware. After passing the verification, write "Please select area B for next startup" in a non-volatile flag. Then reset.

Power on. HSM starts first. Secure Boot checks the boot flag: "Target: Zone B". HSM verifies zone B firmware signature. Passed, Zone B starts. The initialization code of area B firmware performs self-test in the first 30 seconds after running. Check the response of key peripherals, all SWC initialization status, ECC of RAM and Flash. Everything works fine. Confirm that the new firmware starts successfully. Area B becomes the new "operational area".

If zone B fails to start: self-test times out, WDOG bites and resets. The bootloader checks the boot flag again and sees that the number of attempts has not been exhausted. Try again. After retrying for three times and still failing, the Bootloader forcibly switches the boot flag back to area A and resets it. Area A has never been touched. Vehicles are operating as usual. The driver is not even aware that a silent failback has occurred.

**The essence of the A/B partition: at any time, there is at least one complete bootable firmware partition, and this partition is not touched by the ongoing upgrade operation. **

## Start the bootloader: Read the flag and jump to the correct partition

The control core of the A/B partition is a tiny **Bootloader**, which is the only code that "does not participate in rotation" in this firmware upgrade universe. It is placed in an independent area of ​​Flash and does not change with A/B switching.

```c
/* bootloader.c, A/B partition boot boot loader (simplified) */

#define FLASH_PARTITION_A 0x08010000 /* Starting address of area A */
#define FLASH_PARTITION_B 0x08080000 /* Starting address of area B */
#define BOOT_FLAG_ADDR 0x0800f800 /* The sector where the boot flag is located */

typedef enum {
    BOOT_TARGET_A = 0xaa,
    BOOT_TARGET_B = 0xbb,
} BootTarget_t;

typedef struct {
    BootTarget_t target;      /* target partition */
    uint8_t      attempt;     /* Number of boot attempts for the current partition */
    uint8_t      max_attempt; /* Maximum number of attempts (usually 3) */
    uint32_t     magic;       /* Magic number: 0xb007b007 means the flag is valid */
} BootFlag_t;

/* Read startup flag from Flash */
static BootFlag_t boot_read_flags(void)
{
    BootFlag_t flags;
    memcpy(&flags, (void *)BOOT_FLAG_ADDR, sizeof(BootFlag_t));

    /* Check the magic number. If it is invalid, it is either the first power-on or the Flash is damaged */
    if (flags.magic != 0xb007b007) {
        flags.target = BOOT_TARGET_A;
        flags.attempt = 0;
        flags.max_attempt = 3;
        flags.magic = 0xb007b007;
        boot_write_flags(&flags);  /* initialization flag */
    }
    return flags;
}

/* To write the startup flag to Flash, the sector needs to be erased first */
static int boot_write_flags(const BootFlag_t *flags)
{
    /* Flash erase requires the entire sector */
    flash_erase_sector(BOOT_FLAG_ADDR);
    /* Flash programming, writing by word */
    flash_write_words(BOOT_FLAG_ADDR,
                      (const uint32_t *)flags,
                      sizeof(BootFlag_t) / 4);
    /* Verify write */
    BootFlag_t verify;
    memcpy(&verify, (void *)BOOT_FLAG_ADDR, sizeof(BootFlag_t));
    return (memcmp(flags, &verify, sizeof(BootFlag_t)) == 0) ? 0 : -1;
}

/* Main entrance, the first C function executed after the chip is powered on */
void bootloader_main(void)
{
    BootFlag_t flags;
    void (*app_entry)(void);
    uint32_t app_start;

    /* Basic hardware initialization: clock, WDOG, HSM interface */
    system_clock_init();
    watchdog_init();

    /* Read the startup flag without calling any complex functions */
    flags = boot_read_flags();

    /* Determine the target partition address */
    if (flags.target == BOOT_TARGET_B) {
        app_start = FLASH_PARTITION_B;
    } else {
        app_start = FLASH_PARTITION_A;
    }

    /* Increment the startup attempt counter */
    flags.attempt++;
    if (flags.attempt > flags.max_attempt) {
        /* The maximum number of attempts has been reached, switch to the alternative partition */
        if (flags.target == BOOT_TARGET_B) {
            flags.target = BOOT_TARGET_A;
            app_start = FLASH_PARTITION_A;
        } else {
            /* There are no other partitions to fall back to, continue trying area A */
            flags.target = BOOT_TARGET_A;
            app_start = FLASH_PARTITION_A;
        }
        flags.attempt = 1;  /* Give the new partition a chance */
    }
    boot_write_flags(&flags);

    /* Secure boot verification, handed over to HSM */
    if (hsm_secure_boot_verify(app_start) != HSM_BOOT_OK) {
        /* Signature verification failed, firmware has been tampered with or corrupted */
        if (flags.target == BOOT_TARGET_B) {
            /* Return to area A */
            flags.target = BOOT_TARGET_A;
            flags.attempt = 1;
            boot_write_flags(&flags);
            app_start = FLASH_PARTITION_A;
            if (hsm_secure_boot_verify(app_start) != HSM_BOOT_OK) {
                /* The signature of area A is also invalid and cannot be started */
                while (1) { watchdog_kick(); }
            }
        } else {
            /* Zone A signature is invalid and there is no trusted firmware */
            while (1) { watchdog_kick(); }
        }
    }

    /* Get the application entry address, usually the second item in the vector table */
    uint32_t *vector_table = (uint32_t *)app_start;
    uint32_t stack_ptr    = vector_table[0];  /* Initial SP */
    app_entry = (void (*)(void))vector_table[1]; /* Reset_Handler */

    /* Set the main stack pointer, turn off all interrupts, and jump to the application */
    __set_MSP(stack_ptr);
    __disable_irq();

    /* Note: The attempt counter cannot be cleared here, the application is not running yet.
     * After the application self-test passes, the application itself clears attempt;
     * Otherwise, when the application hangs upon startup, the bootloader will retry indefinitely without being able to roll back. */

    /* Jump to the application. After this jump, the bootloader will never run again.
     * (until next reset) */
    app_entry();

    /* Applications should never return */
    while (1) { watchdog_kick(); }
}
```

The code size of the bootloader is very small, usually less than 4KB. It does not participate in A/B rotation and always remains in a separate area of ​​Flash. Its logic is extremely simple: read the flag, select the partition, verify the signature, and jump. Simple logic means fewer bugs, and any bug in the bootloader may prevent the ECU from booting forever.

## OTA download: cut 200MB into small pieces

OTA firmware packages are typically 200+ MB. You can't download it all at once, and the cellular network can go down at any moment. Must be transferred in chunks.

```c
/* OTA_StateMachine.c, OTA upgrade state machine (simplified) */

#define CHUNK_SIZE 4096 /* 4KB per block, matching common Flash sector size */
#define HASH_SIZE 32 /* SHA-256 hash value length */

typedef enum {
    OTA_IDLE,               /* Idle, waiting to start */
    OTA_DOWNLOADING,        /* Downloading, receiving chunk */
    OTA_VERIFYING,          /* Verifying, verifying integrity and signature */
    OTA_ACTIVATING,         /* Activating, write startup flag */
    OTA_ACTIVE              /* The upgrade is completed and the new firmware has taken effect */
} OTA_State_t;

typedef struct {
    OTA_State_t  state;
    uint32_t     total_size;       /* Total firmware size */
    uint32_t     received_size;    /* size received */
    uint32_t     current_chunk;    /* Current chunk number */
    uint8_t      expected_hash[HASH_SIZE]; /* Overall SHA-256 expected value */
    uint8_t      chunk_hash[HASH_SIZE];    /* SHA-256 of the current chunk */
    uint32_t     target_partition; /* Target partition starting address */
    uint32_t     retry_count;      /* chunk retry times */
} OTA_Context_t;

static OTA_Context_t g_ota_ctx;

/* The main loop of the OTA state machine is called periodically by the OTA task */
void OTA_StateMachine_Run(void)
{
    switch (g_ota_ctx.state) {

    case OTA_IDLE:
        /* Waiting for OTA request, diagnostic tool or OTA client trigger */
        break;

    case OTA_DOWNLOADING:
        /* Receive the next chunk */
        if (g_ota_ctx.received_size >= g_ota_ctx.total_size) {
            /* All chunks have been downloaded and entered the verification stage */
            g_ota_ctx.state = OTA_VERIFYING;
        }
        break;

    case OTA_VERIFYING: {
        /* Do SHA-256 on the entire firmware image */
        uint8_t full_hash[HASH_SIZE];
        sha256_calculate(
            (const uint8_t *)g_ota_ctx.target_partition,
            g_ota_ctx.total_size,
            full_hash);

        if (memcmp(full_hash, g_ota_ctx.expected_hash, HASH_SIZE) == 0) {
            /* SHA-256 passes and is handed over to HSM for signature verification */
            if (hsm_verify_signature(g_ota_ctx.target_partition) == 0) {
                g_ota_ctx.state = OTA_ACTIVATING;
            } else {
                /* The signature is invalid, OTA fails, and DTC is reported */
                ota_report_error(OTA_ERR_SIGNATURE);
                g_ota_ctx.state = OTA_IDLE;
            }
        } else {
            /* SHA-256 mismatch, corrupted firmware */
            ota_report_error(OTA_ERR_CHECKSUM);
            g_ota_ctx.state = OTA_IDLE;
        }
        break;
    }

    case OTA_ACTIVATING: {
        /* Update the boot flag, and the bootloader will start the new partition after the next reset */
        BootFlag_t flags = boot_read_flags();
        flags.target = (g_ota_ctx.target_partition == FLASH_PARTITION_B)
                        ? BOOT_TARGET_B : BOOT_TARGET_A;
        flags.attempt = 0;
        boot_write_flags(&flags);
        g_ota_ctx.state = OTA_ACTIVE;

        /* Notify OTA client: upgrade successful, request reset */
        ota_send_response(OTA_RESP_READY_TO_RESET);
        break;
    }

    case OTA_ACTIVE:
        /* The ECU will not actually run the new firmware until the next reset */
        /* The diagnostic tool or OTA client triggers ECU Reset (0x11 0x01) */
        break;
    }
}

/* Called when a chunk is received */
int OTA_ReceiveChunk(uint32_t chunk_num, const uint8_t *data, uint32_t len,
                      const uint8_t *chunk_hash)
{
    if (g_ota_ctx.state != OTA_DOWNLOADING) {
        return OTA_ERR_WRONG_STATE;
    }

    /* Verify SHA-256 of chunk */
    uint8_t computed_hash[HASH_SIZE];
    sha256_calculate(data, len, computed_hash);

    if (memcmp(computed_hash, chunk_hash, HASH_SIZE) != 0) {
        /* Chunk verification failed, request retransmission */
        g_ota_ctx.retry_count++;
        if (g_ota_ctx.retry_count > 3) {
            ota_report_error(OTA_ERR_CHUNK_HASH);
            g_ota_ctx.state = OTA_IDLE;
            return OTA_ERR_CHUNK_HASH;
        }
        return OTA_ERR_RETRY;
    }
    g_ota_ctx.retry_count = 0;

    /* Write to Flash, target partition + offset */
    uint32_t flash_addr = g_ota_ctx.target_partition +
                          (chunk_num * CHUNK_SIZE);

    /* Flash writing: For non-page aligned writes, read-modify-write is required */
    flash_program_page(flash_addr, data, len);

    /* Verify write */
    if (memcmp((void *)flash_addr, data, len) != 0) {
        return OTA_ERR_FLASH_WRITE_VERIFY;
    }

    g_ota_ctx.received_size += len;
    g_ota_ctx.current_chunk = chunk_num;

    /* Store progress, if power is lost, continue from here */
    nvm_save_ota_progress(chunk_num, g_ota_ctx.received_size);

    return OTA_OK;
}

/* Restore after power failure and continue from the last saved chunk */
void OTA_ResumeAfterPowerLoss(void)
{
    uint32_t last_chunk;
    uint32_t received;

    if (nvm_load_ota_progress(&last_chunk, &received) == 0) {
        g_ota_ctx.state = OTA_DOWNLOADING;
        g_ota_ctx.current_chunk = last_chunk;
        g_ota_ctx.received_size = received;
        /* Request the server to continue sending from last_chunk+1 */
        ota_request_resume(last_chunk + 1);
    }
}
```The code size of the OTA state machine is much larger than that of the bootloader, but it still follows a clear principle: **Transmit data reliably over unreliable networks. ** Each chunk is independently verified by SHA-256 to ensure that failure of one chunk verification will not affect previously confirmed chunks. After a power outage, you can resume from the last saved progress without starting from scratch. SHA-256 integrity checking is done by the main CPU, and signature verification is left to the HSM.

## The iron law of Flash physics: why A/B is needed

At this point, a natural question arises: Why can't we just download the new firmware, verify it, and then overwrite it and install it, just like upgrading the app on a mobile phone? Why do we need twice the space?

Because Flash has an iron law of physics.

**Flash cannot be rewritten in place. ** You have to erase the entire sector first: usually 4KB to 64KB, which takes tens to hundreds of milliseconds. The erase operation restores all bits in the sector to 1 (0xFF). Then you program and write new data, turning the bits that need to be changed to 0 every tens of microseconds.

The physics of Flash determine that it can only flip bits from 1 to 0, but not from 0 back to 1. Only sector erase can reset the entire sector to all ones. The granularity of erasure is sector. If you change one word, the entire sector must be erased.

If you try to upgrade in place: read the current sector contents → backup to RAM → erase the entire sector → write the new data into it. If the power is off after erasing but before writing, the sector will be completely erased and in a 0xFF state. **All code is gone. Bricked. **

This is what A/B partitioning solves: upgrade operations are always performed on the "not running" partition. Even if Area B loses power midway through the upgrade, leaving a half-erased mess, it doesn't matter. Area A is intact. Run area A next time.

There's another engineering subtlety here: **Erase is usually much slower than programming. ** A common situation is several orders of magnitude slower, and the specific magnification rate varies with the device. Erasing a 64KB sector may take 200ms. During this 200ms window, the power supply must be stable. The power environment of automotive ECUs is not always stable. Voltage sag on the starter motor, voltage pulses on the generator, glitches before the fuse blows, these can all occur within a 200ms window.

Therefore, a complete Flash writing solution must handle two layers of protection at the same time: **software level** power-down protection: backup sectors before writing, dirty marking mechanism; **hardware level** voltage monitoring: LVD (low voltage detection) circuit triggers NMI interrupt in advance when the power supply drops below the safety threshold, grabbing tens of microseconds to complete the end before the voltage completely collapses.

## Penetration: The essence of Flash erasure - Fowler-Nordheim tunneling

**The essence of Flash erasure is Fowler-Nordheim tunneling: electrons pass through the oxide layer under a strong electric field. **

Each memory cell of NOR Flash consists of a floating gate transistor. Floating Gate: A layer of polysilicon surrounded by an insulating layer of silicon dioxide, electrically isolated from the outside world. Once electrons enter the floating gate, they have nowhere to go. Unless you apply an electric field strong enough for them to quantum tunnel out.

Erase operation: The Flash controller starts the internal charge pump and boosts VDD (3.3V or 5V) to about -12V or +12V and applies it between the control gate and the source. This strong electric field (approximately 10 MV/cm) causes electrons in the floating gate to tunnel through the silicon dioxide barrier back to the channel via Fowler-Nordheim tunneling. The electrons in the floating gate are evacuated. The transistor's threshold voltage returns to the erased state, reading as a logic 1.

Programming operation: The Flash controller applies approximately 5V between drain and source, and the control gate applies approximately 10V programming voltage. The electrons in the channel are accelerated under the transverse electric field, and the "hot electrons" that obtain sufficient energy cross the silicon dioxide barrier under the action of the longitudinal electric field and are injected into the floating gate. The negative charge in the floating gate changes the threshold voltage of the transistor, which reads as a logic 0.**From the HTTP request at your fingertips, to the electrons trapped in the NOR Flash floating gate. ** OTA relies on the entire physical stack: from the CDN edge node to the base station RF, to the cellular modem, to the SPI bus, to the charge pump of the Flash controller, to quantum tunneling in the silicon dioxide layer.

This is what "penetration" means. You don't just see "the file is passed", you see the complete cause and effect chain from the cloud to the floating gate.

## Wear leveling: Flash is not immortal

Flash has a hidden life limit: **Each sector can only survive a limited number of erase/program cycles. **

SLC NAND Flash about 100,000 times. MLC NAND about 3,000-10,000 times. Automotive grade NOR Flash approximately 100,000 times. After exceeding this number, the trapped charges accumulated in the oxide layer cause the tunneling efficiency to decrease, erasing becomes slower and slower, programming becomes more and more unstable, and the data retention time becomes shorter and shorter.

If an ECU records a DTC to Flash every second, the same sector will be erased each time. 100,000 seconds = approximately 28 hours. In a little more than a day, that sector was scrapped.

**Wear Leveling** distributes writes across multiple sectors. It does not always write to the same physical location. Each time it is written to a "new" erased sector, the old sector is marked as "dirty" waiting for erasure recovery. An FTL (Flash Translation Layer) maintains the mapping of logical addresses to physical addresses: logical block 0 is written to physical sector 7 this time, to physical sector 23 next time, and to physical sector 41 the next time.

```c
/* Simplified wear leveling algorithm, finding free sectors with the least number of erasures every time */
uint32_t wear_leveling_allocate(void)
{
    uint32_t best_sector = INVALID_SECTOR;
    uint32_t min_erase_count = 0xffffffff;

    for (uint32_t i = 0; i < TOTAL_SECTORS; i++) {
        if (sectors[i].state == SECTOR_FREE &&
            sectors[i].erase_count < min_erase_count) {
            min_erase_count = sectors[i].erase_count;
            best_sector = i;
        }
    }

    if (best_sector == INVALID_SECTOR) {
        /* There are no free sectors, triggering garbage collection */
        garbage_collection();
        return wear_leveling_allocate();  /* Try again */
    }

    sectors[best_sector].state = SECTOR_ALLOCATED;
    return best_sector;
}
```

Wear leveling is not a matter of OTA. OTA is an entire partition erase and rewrite. Wear leveling is a matter of NvM (Non-Volatile Memory Management): DTC records, calibration data, learning values, these frequently written small data blocks require wear leveling to protect Flash life.

## No one can go back in time: rollback protection

The A/B partition protects you from uninterrupted power, but it does not protect against the evils of human nature.

Assume a scenario: v2.3.1 is pushed to the whole country through OTA. But v2.3.0 has a known high-severity security vulnerability: SecOC's CMAC verification is skipped under certain conditions. v2.3.1 fixes this vulnerability.

Now an attacker has a v2.3.0 firmware image that has been legitimately signed by the OEM, and the signature is fully valid. The attacker somehow pushed this old image to an ECU. The ECU's HSM verifies that the signature matches and is legitimate. ECU launches v2.3.0, back online with fixed security vulnerabilities.

This is **Downgrade attack** (Rollback/Downgrade). The signing mechanism itself cannot prevent the installation of older versions, and signatures of older versions were legal at the time.

**Rollback Counter** (Rollback Counter) is targeted at this attack surface.

The HSM internally maintains a monotonically increasing counter, stored in an OTP or physically protected memory block. Its physical characteristics are: ** can only increase, not decrease. ** This is not guaranteed by software logic, but by the hardware design of HSM.

The manifest of each OTA upgrade package carries a version number. After HSM verifies the signature, it does an additional check: Is this version number ≥ the value of the current rollback counter? If so, the upgrade is accepted and the counter is updated to the new version number. If not, reject, even if the signature is perfectly legitimate.

**Old versions can never be replayed. ** The attacker has a fully legitimately signed old firmware in his possession. HSM said: "This version of yours is lower than the version I have seen. You are outdated and I don't accept it."

Downgrade attacks are blocked. Old firmware carries old vulnerabilities and can never be returned to the system.

OTA is your ultimate commitment to a device that will never be touched by your hands again.Once a car leaves the factory, it doesn't come back to your factory for the next 15 years. But it might do 500,000 kilometers. Passing through the equator and the Arctic Circle. The screws were loosened by the jolt. Being bombarded with electromagnetic interference. It was parked in an underground garage without moving for three years.

In those 15 years, you may only get one chance to upgrade it, via OTA. No physical contact, no JTAG debugger, no production line programmer.

You have to trust your A/B partitions and fall back to A if partition B breaks. You must trust your HSM signature verification, tampered firmware will not boot. You must trust that your Flash power-off protection will not lose data even if the power is turned off. You have to trust your rollback counter that old vulnerabilities won't reappear.

An ECU that operates in an unreliable power supply, unreliable network, and unpredictable physical environment. But you have to guarantee: among all these uncertainties, the probability of getting bricked is infinitely close to zero. 

This is the responsibility of the OTA engineer. It's not "the code is sent out and that's it." What you are betting on: Any day in the distant future, anywhere in the world: **"The upgrade logic you wrote back then will not kill this car."**
