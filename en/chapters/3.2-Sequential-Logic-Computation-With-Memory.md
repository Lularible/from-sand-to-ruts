# 3.2 Sequential Logic: Computation With Memory

## At the clock edge, save the bit

You stare at the oscilloscope screen.

On channel 1 is a nice square wave: 100MHz, 10ns period. On channel 2 is the data signal: a bunch of 0s and 1s flipping around like crazy. You said something to the signal:

"On the next rising edge of the clock, save this bit."

At this moment, you are asking the circuit to have "memory".

In the previous section, we talked about combinational logic, that is, a function whose output is always equal to the current input. But what you said about the signal means: the output is no longer just a function of the current input, the output depends on what the input is at the moment the clock edge arrives. And this value will be maintained until the next edge.

This requires a completely new component.

## D flip-flop: 1 bit memory

The most basic unit of memory is called **D flip-flop** (D Flip-Flop, FF).

It has only one data input (D), one data output (Q), and one clock input (CLK). The behavior is simple enough to be described in one sentence:

```
On every rising edge of CLK: Q ← D
The rest of the time: Q remains the same
```

```
CLK:  _|¯|_|¯|_|¯|_|¯|_|¯|_
D  :  ___ ¯¯¯¯¯¯ _______ ¯¯¯¯
Q  :  _________ ¯¯¯¯¯¯ ______
              ↑       ↑
         First rising edge Second rising edge
```

A D flip-flop stores **1 bit** of information. How does it "hold"? The internal structure is actually very elegant: two latches are cascaded, and each latch works alternately in transparent/latched modes. When CLK=0, the master latch is transparent and the slave latch is latched; when CLK=1, the reverse is true, and the data is "shot" from D into Q at the moment of the rising edge of CLK, and then is locked.

Put N D flip-flops together and use the same CLK, this is an **N-bit register**.

Your ARM Cortex-M4 has 16 registers (R0-R15), 32 bits each. R0-R12 are general registers, R13 is SP, R14 is LR, and R15 is PC. These 16 registers total 16 × 32 = 512 bits, plus status registers such as PSR, there are hundreds of flip-flops in the register file, driven by the clock.

### Simulate D flip-flop in C

Let's simulate a D flip-flop in software, including setup and hold time checks:

```c
#include <stdint.h>
#include <stdio.h>

typedef struct {
    int q;                  // current output
    double t_setup;         // Setup time (ps)
    double t_hold;          // Hold time (ps)
    double t_cq;            // Clock-to-Q delay (ps)
    int metastable;         // metastable flag
} D_FlipFlop;

void dff_clock(D_FlipFlop *ff, int d, double d_change_time,
               double clk_edge_time) {
    // Check setup time: data must be stable before clock edge t_setup
    if (clk_edge_time - d_change_time < ff->t_setup) {
        ff->metastable = 1;
        ff->q = -1;   // Uncertain value
        return;
    }

    // Check the hold time: data cannot change within t_hold after the clock edge
    //(Scheduler support is required in full simulation, simplified here)

    ff->metastable = 0;
    ff->q = d;   // Normal sampling
}

void demo_dff() {
    D_FlipFlop ff = {0, 50.0, 20.0, 100.0, 0};

    // Normal sampling: data is stable 80ps before edge (>50ps settling time)
    dff_clock(&ff, 1, 100.0, 180.0);
    printf("Q = %d (normal)\n", ff.q);  // Q = 1

    // Settling time violation: data changes 30ps before edge (<50ps settling time)
    dff_clock(&ff, 0, 250.0, 280.0);
    printf("Q = %d, metastable = %d (Metastable!)\n",
           ff.q, ff.metastable);  // Q = Not sure
}
```

This simulation captures the key :D The behavior of triggers is not "instant". The data cannot change near the clock edge, it needs a quiet period. Violation of this requirement causes the flip-flop to enter a metastable state.

## Synchronous sequential circuit: combinational logic + register

When you combine combinational logic and registers, you get a synchronous sequential circuit:

```
  +--------+     +--------+     +--------+
  | Reg |────>| Logic |────>| Reg |────> ...
  | (FFs) | | logic | | (FFs) |
  +--------+     +--------+     +--------+
       ↑                          ↑
      CLK                        CLK
```

Every clock cycle:
1. The front-stage register outputs stable data.
2. Combinational logic uses this beat of time to propagate and calculate.
3. The result is "shot" into the subsequent register on the next rising edge.

This is the basic skeleton of all synchronous digital circuits. From the simplest counter to the most complex multi-core SoC, they are all recursive nesting of the same set of structures: register → combinational logic → register → combinational logic → register... like a set of pipelines connected end to end, stacked layer by layer until the entire digital world is constructed.

### A 4-bit counter: the simplest example of sequential logic

```c
#include <stdint.h>

typedef struct {
    uint8_t value;     // 4-bit count value
    uint8_t enable;    // enable
    uint8_t reset;     // Synchronous reset
} Counter4Bit;

void counter_clock(Counter4Bit *ctr) {
    // Synchronous reset (sampled on the rising edge of clock)
    if (ctr->reset) {
        ctr->value = 0;
        return;
    }

    if (ctr->enable) {
        // Use the full adder logic defined in the previous section: add 1
        int a[4] = {ctr->value & 1, (ctr->value>>1)&1,
                    (ctr->value>>2)&1, (ctr->value>>3)&1};
        int one[4] = {1, 0, 0, 0};
        int sum[4], c_out;
        ripple_carry_adder(a, one, 0, sum, &c_out);

        // 4-bit wrap: ignore c_out
        ctr->value = sum[0] | (sum[1]<<1) | (sum[2]<<2) | (sum[3]<<3);
    }
    // No enable: keep the original value
}
```

This 4-bit counter is incremented by 1 on the rising edge of CLK when enabled and reset to zero. It has only 4 D flip-flops and a 4-bit adder. But scale it up to 64 bits, add a start value, and use a capture signal. You get the core of the PTP (Precision Time Protocol, used for nanosecond clock synchronization in distributed systems) hardware clock (PHC). PTP is a huge counter inside the clock that starts from 0 and counts around the clock, counting the period of the local oscillator. When the PTP message arrives, the hardware latches the count value at that moment, which is the hardware timestamp. All done with a string of D flip-flops and adders.

### Shift register

Connect N D flip-flops in series, and connect the Q of the previous one to the D of the next one, and you will get a **shift register**. Each clock cycle, the data is shifted one bit to the right.```
CLK:     _|¯|_|¯|_|¯|_|¯|_|¯|_|¯|_
D_in:    ___ ¯¯¯¯ _____ ______________
Q0:      ______ ¯¯¯¯ _____ __________
Q1:      _________ ¯¯¯¯ _____ _______
Q2:      ____________ ¯¯¯¯ _____ ____
```

The shift register is the physical basis for serial-to-parallel conversion (SPI data reception) and parallel-to-serial conversion (SPI data transmission). The transmitting end of the UART is also a shift register. Parallel data is loaded in, clocking out one bit per baud rate to the TX line.

## Three key timing parameters

But the action of "shooting" is not magic, and the D flip-flop has strict timing requirements.

- **Setup time**: The minimum time the data must settle before the clock edge. If the data is still changing within the establishment time window, what FF captures may be 0 or 1, or even an intermediate level. This is called metastability.
- **Hold time**: The data must continue to remain stable for a period of time after the clock edge.
- **Clock-to-Q delay**: The time it takes for new data on the Q terminal to be stably output after the clock edge.

Picture a subway car door. You have to step into the car before the doors start to close. This is Setup Time. When the door is halfway closed, you can't put another foot in. This is Hold Time. If Setup is violated, you are caught in the door (metastability). If Hold is violated, your feet will also be clamped (also metastable). The clock edge of the D flip-flop is the closing door.

The maximum frequency of the entire digital circuit is determined by this formula:

f_max = 1 / (T_cq + T_comb + T_setup + T_skew)

Among them, T_comb is the maximum path delay of the combinational logic between the two-level registers, and T_skew is the clock deviation, which is the time difference between the same CLK arriving at different FFs.

In a typical process, more than a dozen levels of logic gates are placed between two levels of registers, each level taking about tens of picoseconds. T_cq, T_setup, and T_skew are all on the order of tens to hundreds of picoseconds. A 15-level logic-depth path has a total latency of about a few hundred picoseconds and f_max in the 1-2 GHz range.

However, if you switch to the worst process corner (slow NMOS, slow PMOS), high temperature, and low voltage conditions, the gate delay of each stage may increase by more than 50%, and T_cq will also increase significantly. For the same design, the maximum frequency can differ by 50% under different process angles. This is why the chip is marked with "operating frequency range" instead of "fixed frequency". It's not that it doesn't want to be stable, but it's physically unable to be stable.

This is why the IC can run at GHz internally, but the discrete chip solution can only run at MHz. The traces inside the IC are extremely short, the clock skew is controllable, and the gate delay is minimal. The PCB has long traces, large capacitance, and lots of electromagnetic interference, so both T_comb and T_skew are much larger.

## Metastable state: when the trigger is "indecisive"

Metastability was mentioned above. This is a concept that deserves special discussion because it is a core issue in all clock domain crossing (CDC) designs.

There is a positive feedback loop inside the D flip-flop, with two inverters connected end to end. Under normal operating conditions, this feedback loop is forced to 0 or 1. But if the data changes within the settling time window, the input latch may capture a voltage between V_IL and V_IH, which is neither a clean 0 nor a clean 1.

At this time, the two inverters in the feedback loop will enter the linear region. They act like an amplifier, trying to amplify the input to full rail. But if the input voltage happens to be the metastable point of the feedback loop (about VDD/2), the gains of the two inverters happen to make the output equal to the input, and the entire loop stays at the intermediate voltage.

But it won't stay in the middle forever, and thermal noise will eventually tip the balance, causing it to drop to 0 or 1. However, the time required for this process is uncertain. It may be one clock cycle or hundreds of clock cycles. During this time, subsequent logic circuits may see a 0, may see a 1, may see an oscillation, which means that the calculation results are not repeatable.This is why synchronizers (two or three levels of D flip-flops in series) must be placed when crossing clock domains, giving the first flip-flop enough "Mean Time Between Failures" (MTBF) to recover from metastability. The MTBF of two-level synchronizers is typically in the upper decades (for a 200MHz clock domain), but for ASIL-D systems, a three-level synchronizer or asynchronous FIFO is usually required.

Metastability is not a design error, it is a physical law. You can't eliminate it, you can only reduce its probability to an acceptable range.

## PTP Hardware Timestamps: The Ultimate Application of Triggers

Now back to PTP.

The PTP slave clock needs to record the precise moment when the packet arrives at the MAC layer, and the accuracy is required to be at the nanosecond level. How?

How modern Ethernet MACs that support PTP (such as the TI DP83640) do this:
1. Monitor the transition of the RX_DV (receive data valid) signal on the MII/RMII interface.
2. The moment RX_DV becomes high level, the hardware circuit generates a **capture signal**.
3. This capture signal triggers a set of registers (i.e., D flip-flop array) to latch the count value of the current PTP hardware clock (PHC).

The entire process is completed at the physical layer, with latency of only a few nanoseconds and jitter at the sub-nanosecond level. There is no interrupt response time, no software processing delay, and no operating system scheduling uncertainty, because it is all flip-flops and combinational logic that do the work.

How does PTP achieve nanosecond accuracy? The answer is: It completely hands over the matter of "recording time" to a counter running at a fixed frequency + an edge-triggered latch D flip-flop group. This is pure hardware without any software uncertainty.

In the PTP's PI servo controller, the frequency correction value is written into the frequency adjustment register of the PHC, which is essentially an adder. Each clock cycle accumulates the frequency correction value into a phase accumulator, and generates a clock tick when it overflows. This is also pure sequential logic. The essence of the high precision of the PTP protocol is not in the software, but in the hardware, in those flip-flops that are flipping day and night.

Software timestamps cannot achieve this accuracy because software only polls or interrupts. Even on RTOS, response latency is in the order of microseconds, which is three orders of magnitude worse. **

The D flip-flop you learned in mathematics class, this seemingly basic unit, is the physical basis of PTP hardware time stamping.

## From "dead things" to "living things"

Combinational logic is a "momentary truth": the output is always a function of the current input.

Sequential logic is "historical memory": the output is not only a function of the current input, but also carries traces of the past.

This "memory" ability turns circuits from "dead things" into "living things". Any system you design is essentially a balance between "computation" and "memory".

When you write a CAN diagnostic state machine in the ECU, every state transition: from "default session" to "extended session" is a set of D flip-flops that update their values ​​on the clock edge. The accumulated historical offset of PTP's PI servo controller is used for frequency correction. Each increment of the "integral term" is latched in a register, waiting to be read out in the next Sync cycle. Memory means circuit learning, etc.

Your ECU is not just "calculating", it is using memory to assist calculations and using calculations to protect memory.
